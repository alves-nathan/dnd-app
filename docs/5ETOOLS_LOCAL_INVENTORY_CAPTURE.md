# a8.13.2 — Read-only inventory observation adapters

The capture coordinator accepts only a store reader and getItem storage port. Captures initial aggregate evidence and reference guards, reads three selected raw keys twice (legacy compendium envelope, package index, download cache index), and recaptures the store evidence. Rejects changed raw strings, changed guard references, changed observed fingerprints and busy/changed sessions. Missing/corrupt/failed raw reads never become synthetic empty indexes. Stable observation means only these reads agreed, not a transaction, durability or completeness. Raw content stays local; only aggregate evidence is returned.

The explicit store adapter reads the already hydrated compendium/catalog/portable state, character reconciliation, trust and update/restore session snapshots. Uses existing pure portable checkpoint capture; no hydration, repository factory, bootstrap, repair or mutation. Loaded compendium is store-derived rather than an independent authoritative backend read. Direct SQLite load can initialize/migrate and is intentionally not called. Package chunks, remaining auxiliary stores, raw active backend and external inventory remain notInspected. No UI or startup wiring. No package trust/rights verification. A capture cannot exclude ABA/external writes or certify all stores.

Four synthetic cases use existing disposable repository fixture and storage reader. No new workflow/dependency. Next a8.13.3: extend strict read-only inventory to auxiliary stores, package descriptors/chunks and independent active persistence where safe; add explicit coherence evidence and later UI. No backup/migration approval.
