# a8.13.7 — Runtime and portable reference obligations

Pure local review takes the same capture ID, explicit installed/loaded/portable snapshots and a caller-supplied baseline runtime occurrence list. Recomputes the evidence digest and all three core fingerprints and counts; fails on stale/mismatched observations or duplicate baseline IDs. Accounts for each baseline runtime entry as exact, changed or missing, and each additional loaded entry as loaded-only. Baseline provenance and historical ledger join remain separate obligations; caller-supplied baseline is not authenticated.

Inventories explicit character/preset compendium links (origin-qualified, exact storage ownership or catalog ID), character snapshot refs, scenario/character and history/character/scenario refs, and book/category/entity filter keys. Removed links preserved, unqualified links not guessed, missing/ambiguous/owner mismatch not repaired. Historical absence is review only, not deletion. No alias/provider/choice resolution. Returns aggregate counts and row fingerprints only. Four acceptance criteria remain partial/pending, none accepted. Does not inspect all build choices, tactical participants, recovery/quarantine payload refs, registry/edge/category/alias identity, independent backend bytes or external inventory. No screen wiring or actual device inspection. Three synthetic tests in existing suite.
