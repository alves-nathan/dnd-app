# a8.13.5 — Inventory disposition ledger

Rebuilds the existing a8.1 migration preview and refuses stale, modified or integrity-failing previews. Requires zero approved reconciliation mappings/parity and no retirement approval. Accounts separately for each historical physical occurrence, installed storage row, missing baseline row and baseline runtime occurrence. Qualified matching requires import ID, kind and source ID; raw JSON digest distinguishes exact occurrence(s) from payload differences. Repeated IDs/occurrences remain distinct. Existing storage ownership/disposition, normalized JSON, source/pack fingerprints, enabled state and explicit review markers are preserved. Manual review markers are not a complete detector of manual edits. Exact raw matches neither prove pack ownership nor confer mechanical equivalence. No name matching.

Optional exclusion proposals bind a specific row fingerprint and limited reason code; duplicate/stale/unknown proposals rejected. All proposals remain unapproved and every row is preserved, including local absence. No deletes, writes or activation. Aggregate-only structural audit output; full ledger stays in memory (no raw texts or private inventory exported). Reuses current bundled fixture audit and accepts explicit local snapshots offline; not connected to the live panel, actual installed data, runtime/portable capture or external inventory. Independent SQLite/IndexedDB coverage remains pending.

Three synthetic regression cases plus the existing real bundled audit. Next a8.13.6: bind ledger to local inventory observation and define portable, read-only review of outstanding dispositions without treating fixture baseline as installed truth.
