# a8.10.1 — Remaining family inventory

Accounts for every historical occurrence, every staging runtime entry and every emitted pilot item using the existing reconciliation inputs. Coverage lanes distinguish prior scoped checkpoints, equipment/magic item/creature evidence and kinds outside the V3 pilot. A prior checkpoint is not mechanical approval. Runtime class/subclass feature kinds are grouped only for lane classification and target checks; original kinds remain counted separately.

For the three remaining families, compares selected payload and mechanics paths independently, including absent, added, missing and differing values; counts unassessed fields. Retains individual historical occurrences and fingerprints, source-qualified physical IDs and magic template/base identity. Inventories source declarations and converter review codes, not inferred effects. Runtime-only contracts remain preservation obligations; this is not an installed character inventory or independent source authentication.

Uses existing snapshots, no new clones, workflow, dependencies, runtime changes or upstream payload publication. Aggregate counts and report fingerprint only. No mapping, parity, retirement or execution approval.
