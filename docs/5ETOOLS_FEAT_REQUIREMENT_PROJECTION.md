# a8.9.2 — Feat requirement projection

Rebuilds a8.9.1 evidence and checks its digest if provided. Re-derives prerequisite trees from the retained upstream record; rejects divergent converted trees. Projects level, ability, three distinct spellcasting facts, class level and explicit feat/optional-feature references, preserving AND/OR with three-valued evaluation. Emitted endpoints require physical IDs, source code, upstream commit and the same known edition. Missing sources, special qualifiers, unsupported predicates, self-references and missing endpoints remain pending. This is not independent raw source authentication or a proof of complete endpoint coverage.

Category codes are matched exactly to the converted value; no default for legacy uncategorized feats. The caller supplies and explicitly confirms the allowed category set for the specific hypothetical context, rather than inferring origin, class or epic boon acquisition policies. Level bounds, ability bounds, class totals and supplied physical IDs are checked. Missing facts are unknown unless the caller confirms completeness; no live character fact extraction is performed. A satisfied OR branch may prove a selected prerequisite despite another pending branch. An absent prerequisite is not an eligibility approval. Repeatability, allocation, choice, resource and grant policies remain pending.

The preview rebuilds evidence and checks projection and feat fingerprints. It never writes or grants; requirementsCandidate means only the selected prerequisites and caller-confirmed category set were satisfied. Logs are aggregate only; no workflow, runtime or upstream payload changes. Next a8.9.3: ASI allocation and repeatability/instance boundaries.
