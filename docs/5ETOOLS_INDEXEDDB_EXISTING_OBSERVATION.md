# a8.14.3 — Existing-only IndexedDB observation

The audit-only path requires indexedDB.databases() and an exact known database name/version before opening. No ordinary initializing adapter call, createObjectStore, deleteDatabase, put or readwrite transaction. Enumeration is not atomic: a racing deletion may trigger an attempted creation, and an upgrade event is always aborted so no version change is committed. Blocked open, timeout, mismatched schema or missing API fail closed. Late open success closes immediately; upgrade handler remains installed after timeout. Uses one readonly transaction, requires request success AND transaction completion, distinguishes missing key and wrong value type; closes connection after completion or error. A raw value stays in process and is consumed by the strict existing envelope observer. Active repository identity guard and existing double-read capture/panel support webSnapshotMatch without fallback.

Five disposable event-driven test cases: no open if absent/unknown/mismatched, readonly successful read, invalid/missing values, raced upgrade abort, late blocked success, transaction abort and missing store, capture match and changed reads. These are mocks, not proof on actual browsers. No new dependencies or workflow jobs. Existing production read/write paths unchanged. Real browser compatibility, native SQLite, concurrent ABA and late changes, auxiliary persisted stores, and owner inventory remain pending. Next a8.14.4: independent persistence verification protocol and real adapter evidence harness (no production writes; disposable fixtures only). No gate acceptance.
